# RPFM Server 5.3.1 — verified GHCR images

## What's changed

* The action now downloads a verified RPFM image from GitHub Container
  Registry instead of compiling the backend in every consumer job.
* Each release includes `rpfm-image.json`, which binds an OCI digest to the
  backend version, source/schema pins, platform and Docker build inputs.
* The publisher tests an anonymous download of the exact digest, then
  promotes its version tag and attaches the lock. Images include SBOM,
  build provenance and a GitHub OIDC attestation.
* Docker Compose now downloads the release image. A separate Compose
  override and `build-from-source` action input retain explicit source builds.
* Root and `/server` actions share one launcher, with failure cleanup and
  an `image` output for inspecting the actual reference used.

## Usage

```yaml
- uses: Warhammer-Mods/rpfm-server-docker@v5.3.1-server.2
  id: rpfm
```

Requires a Linux x86-64 runner with Docker. Public images need no registry
login. Stop the returned container in an `always()` cleanup step.

## Compatibility

The backend remains RPFM 5.3.1 with API v2. Existing `image` and `port` inputs
and `url`, `mcp-url`, `container` outputs remain available. The default now
requires the published release image metadata; it does not silently build
from source. Development refs can set `build-from-source: 'true'`.
